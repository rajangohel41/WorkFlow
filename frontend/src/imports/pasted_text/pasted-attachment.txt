# WORKFLOW — MASTER FULL FUNCTIONALITY & INTERACTION PROMPT

## CRITICAL REQUIREMENT

Upgrade the existing WorkFlow frontend from a visual prototype into a **fully interactive frontend application**.

The current UI contains many buttons, dropdowns, filters, tabs, menus, cards, forms, navigation items, and actions.

### ABSOLUTE RULE

**NO VISIBLE INTERACTIVE ELEMENT MAY BE NON-FUNCTIONAL.**

If a button, icon, dropdown, menu, tab, card, link, form, filter, search field, checkbox, switch, table action, Kanban action, or navigation item is displayed to the user, it must perform a meaningful action when clicked or interacted with.

Do NOT leave:

* Dead buttons
* Dead links
* Fake dropdowns
* Fake search
* Fake filters
* Fake tabs
* Fake modals
* Fake notifications
* Fake CRUD actions
* Buttons that do nothing
* "Coming soon" placeholders
* Console-only actions
* UI that changes visually but does not update application state

The application should behave like a **real frontend product**, even though it uses mock/local data instead of a backend.

# 67. FINAL RULE

DO NOT rebuild the existing design from scratch.

Keep the existing visual design.

**Upgrade the functionality underneath it.**

The final result must satisfy this rule:

> **If the user can see it, the user can interact with it. If the user interacts with it, the application must respond correctly.**

No dead UI.

No fake controls.

No unfinished interactions.

No placeholder buttons.

No decorative-only operations.

Every operation should have:

**Action → State change → UI update → Feedback**

For example:

```text
Create task
↓
Loading
↓
Task created
↓
Task appears in list/board
↓
Dashboard counts update
↓
Success toast
```

This principle must be applied consistently throughout the entire WorkFlow application.

The finished frontend should behave like a **complete, realistic SaaS application powered by mock services**, ready to have a real Express/MongoDB backend connected later.
